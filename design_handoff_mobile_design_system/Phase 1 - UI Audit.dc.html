⚑ Flagged
Four parallel systems express the same three meanings (good / warning / bad). .badge.keep|hold|cut, .need-pill.deep|short, .why-chip.good|warn, and .card.good|bad each re-encode success/warning/danger — one with an rgba tint, one with a border hex, one with both. A single semantic pair (--success-fg / --success-bg) replaces 14 declarations.
Two border colors, 6% apart. --border #2a3039 for containers, bare #20252e for row dividers in table.grid td, .scar-row, .prospect. Intentional (dividers should be quieter) but untokenised, so it reads as a mistake.
Position colors are a fifth palette. The four .pos-* chips use lightened one-off hexes (#ff8f8f…) over a tint of a different hex (rgba(255,107,107,.15)). QB red is also the danger red — a QB chip and a "cut" badge are the same color, which is the one collision that actually misleads.
Contrast: --dim #8b95a3 on --bg ≈ 6.4:1 — fine for body, but it is used at 11px and 12px in 20+ places (table headers, card labels, chips), where it sits under the recommended size for that weight. The 9px .wk-num chart labels are effectively unreadable on a phone.

⚑ Flagged — mobile
Every input and select is 13px. iOS Safari auto-zooms any focused form control under 16px, then leaves the page zoomed. The player search on Players, all six filter selects, the team picker in the header and the value-override field all trigger it. This is the single most visible mobile defect in the app.
13px is doing too much work. 14 of the ~40 text rules are 13px — controls, body prose, chips and table meta all share it, so nothing is visually ranked. There is no step between 14 (body) and 18 (h1 on mobile).
Two uppercase micro-label styles. h3 / th / .pill-active / .arch-pill use 0.04em tracking; .card .k uses 0.05em at a different size. Same intent, two recipes.

⚑ Flagged
Three different toggle-group implementations. nav (top-level tabs, .active), .subtabs (Team, Players, Tiers, Market — .active, track container) and .subtabs-btn (the QB/RB/WR/TE filter on Tiers — .on, no track, extra border color #35507d). Same interaction, three visual languages, two state-class names.
No primary button exists. The most consequential actions — Refresh, "Reset to recommended" — reuse .refresh, a rule that also styles every <select>. A destructive/primary distinction can't be expressed at all.
Player names are 21px-tall tap targets and they open the drilldown modal — the primary interaction on six of eight screens. In the keeper table they sit next to a 13px checkbox in a row 37px tall, on a 390px screen, inside a horizontally scrolling container.
Hover-only affordances on a touch device. .ov-edit reveals its dashed border on hover, table tr:hover is the only row feedback, and .plink only underlines on hover. On a phone none of these ever fire — the editable Worth cell is invisible as a control.

⚑ Flagged
The stylesheet contains no :focus or :focus-visible rule. Not one, across 17.6 KB. Every custom button sets border: 0 on a transparent background, so keyboard focus falls back to the UA outline over a dark panel where it is barely visible — and the modal has no focus trap or scroll lock either.
No disabled, error, placeholder or loading styling. .refresh is rendered with disabled while refreshing but looks identical; the label just becomes "…". Checkboxes are native at ~13px with only accent-color set — the keeper simulator is driven entirely by them.

⚑ Flagged — highest impact
Navigation disappears on scroll. The header is sticky on desktop and explicitly static on mobile — so on the one viewport that matters, the tab switcher, team picker and value-source picker all scroll away. On the Players table (hundreds of rows) getting back to nav means scrolling to the top. And the switcher itself is a native <select> at the very top of the screen: the least thumb-reachable position on the page, presented as the least discoverable control.
Eight-column tables become horizontal scrollers. table.grid { display:block; overflow-x:auto } with white-space:nowrap on every cell. The keeper board (checkbox · Player · Pos · Acquired · Worth · Keep $ · Surplus · Call) needs ~640px; on a 390px screen the Surplus and Call columns — the entire point of the screen — are off-canvas, with no column freeze and no scroll affordance.
Nested scroll containers. .table-scroll caps height at 65vh and scrolls vertically, while the table inside it scrolls horizontally, inside the page which scrolls vertically. On Players, Targets and Last-year auction that's three scroll axes in one thumb zone. 65vh also fights mobile browser chrome.
The modal is a desktop dialog on a phone. 6vh 16px padding, max-height:86vh, a 27px ✕ in the top-right corner — the hardest point on a phone to reach — no bottom-sheet treatment, no drag-to-dismiss, no body scroll lock, no safe-area padding. Its 18-bar weekly chart with 9px labels renders inside a 358px-wide box.
Two breakpoints for one job. .two-col collapses at 800px, everything else at 760px — so between 761 and 800px the layout is half-mobile. Both are desktop-down queries: the CSS is written desktop-first for an app that is used on phones.

09 — Priority

What to fix, in order

1
Persistent thumb-reachable nav. Bottom tab bar with safe-area inset; retire the mobile <select>.
2
16px minimum on every form control + a 44px control height token. Kills the iOS zoom bug and every sub-44 target at once.
3
A mobile row pattern to replace horizontal-scroll tables on Team, Players, Targets, Market.
4
Semantic color tokens. Collapse 28 colors → ~14 named roles; one success/warning/danger pair replaces four parallel systems.
5
One button component with primary / secondary / ghost / segmented variants — replaces 10 treatments and 3 toggle groups.
6
Type scale + 4pt spacing scale. 14 sizes → 7 steps; 21 spacing values → 7.
7
Bottom-sheet modal with focus trap, scroll lock and a reachable dismiss.
8
Focus-visible ring, chip primitive, icon set — cleanup once the above land.
